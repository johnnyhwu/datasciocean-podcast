# Gemini TTS 實測筆記(2026-09-06)

模型 `google/gemini-3.1-flash-tts-preview`,透過 OpenRouter `/api/v1/audio/speech`。
所有結論都來自本專案的實測,不是文件轉述。

## 二、它讓正規化層縮水一半以上

用完全未改寫的原文直接餵進去,STT 回轉:

| 原始寫法 | 結果 |
|---|---|
| `監督式微調`、`消融實驗`、`這個主張` | ✅ 1.000 — **三個 Breeze 修不掉的破音字全對** |
| `SFT` `RLHF` `LLM` `RAG`(未加點) | ✅ 1.000 — **R1 加點規則不需要** |
| `rm -rf`、`預設` | ✅ 1.000 |

| `GPT-4o` `GPT-4o-mini` | ✅ 1.000 |
| `RL` `PPO` `GRPO` | ✅ 1.000 |
| `Stage 2` | ✅ 0.977 — **不再變成「Stage Wu」** |

仍然會壞、**必須保留改寫**的:

| 原始寫法 | 唸成 |
|---|---|
| `ρ = -0.44` | 「**Row** 等於負 0.44」 |
| `5e-6` | 「**51-6**」 |

R1、R6、R7、R8 對 Gemini 是多餘的。

另外 **幽靈音完全消失** —— 那是 Breeze 獨有的病,不是通病。

## 三、風格控制:提示越短越好(反直覺)

Gemini 沒有 `emotion` 之類的參數。控制方式是把指示寫進 `input` 前綴,
**實測確認指示不會被唸出來**(轉錄裡一個字都沒有)。

因為控制手段是文字而非參數,**走 OpenRouter 在語氣控制上零損失**。

但長度是個陷阱,實測三個量級:

| 提示長度 | 結果 |
|---|---|
| 577 字(markdown 導演筆記) | ❌ **穩定回傳 502 空音訊**,連續 7 次全失敗 |
| 146 字(壓縮版) | 🔶 可用,但語氣被稀釋,sim 0.984 |
| **40 字** | ✅ **最好聽,sim 1.000** |

失敗方式有兩種,都遇過:
1. HTTP 200 但空音訊 → OpenRouter 轉成 502
2. 回傳 6.6MB(正常 1.2MB)→ **把整份提示唸出來了**

診斷過程中試過拿掉 `#`、加回行首空格、去掉撇號,都無法穩定;
唯一可靠的解法是**縮短**。

**教訓:導演筆記那套格式是為 AI Studio 的獨立欄位設計的。
走 API 時提示跟正文擠在同一個 `input`,長提示會跟正文搶注意力。**

### 真正的觸發條件是「提示 / 正文」的比例,不是絕對長度

後來在整集生成時,一個 45 字提示配 24 字的短路標又掛了。控制變因實測:

| 提示 | 正文 | 結果 |
|---|---|---|
| 45 字 | 24 字 | ❌ 502 |
| 45 字 | 24 字(只換標點) | ❌ 502 |
| **無提示** | 24 字 | ✅ 200 |
| **7 字**(「請用台灣口音說。」) | 24 字 | ✅ 200 |
| 45 字 | **32 字**(正文加長) | ✅ 200 |

**提示相對正文太長就會失敗。** 短 signpost beat 是高風險族群,
因為它們正文本來就短。

### 因應:提示自動降級

`pipeline/tts.py` 準備一組由長到短的提示,失敗就降一級:

```
完整 role 提示  ->  只留骨幹那句  ->  「請用台灣口音說。」  ->  完全不帶提示
```

寧可少一點語氣也要有音檔。降級時會印出用到第幾級,方便事後檢查
哪些 beat 的語氣沒吃到。另外全部降級都失敗時**記錄並跳過,不中斷整集** ——
先前一段失敗就整批中止,69 段跑到第 14 段全毀。

### 定案的做法:固定骨幹 + role 語氣尾巴

```
請用台灣人的口音說話,像台北的科技 podcast 主持人那樣。<role 語氣>
```

全部控制在 40-50 字。14 個 role 各一句(中英文都有),見 `.claude/skills/podcast/SKILL.md` 的對照表。

### 台灣腔

用中文明示口音有效(`a2_tw_zh` 是人耳選出來的最佳版本)。
英文指示、BCP-47 語言碼、列舉語音特徵(捲舌/兒化)都試過,
中文短句最好。**但這是提示引導,不是原生台灣腔** —— 若最終不滿意,
只能換 Azure `zh-TW` / ATEN / 雅婷這類原生服務。

### 行內標籤

`[laughs]` `[curious]` 有效且不會被唸出來(轉錄乾淨)。
`tag_Puck` 開頭多了一個「哇」,是笑聲被 Whisper 聽成字 —— 代表真的演出來了。
建議每集 1-2 次為上限。

## 四、三個必須知道的限制

### 1. `seed` 無效 —— 沒有可重現性

實測同一請求帶同一 seed 跑兩次:md5 不同,音檔長度差 12%(161KB vs 142KB)。
連跑 5 次的長度落在 26-32 秒之間,變異 23%。

**重跑就是重骰,不能鎖定。** 這比 Breeze 差(Breeze 的 seed 是真的)。

### 2. 官方承認音色會漂移

> "The model's output may not always strictly match the selected speaker,
> causing the audio to sound different than expected."

> "Speech quality and consistency may begin to drift with generated outputs
> longer than a few minutes. We recommend splitting your transcripts into
> smaller chunks."

好消息是官方建議的做法(切小塊)正是我們的 beat 制度(PLAN.md §4.5)。
且預建音色是**固定的身分目標**,不像 Fish/BlueMagpie 每次從參考音檔重新推斷 ——
後者正是「聽起來像不同人」的成因。

### 3. 不能克隆你的聲音

Gemini TTS 只有 30 個預建音色,沒有上傳音檔的路徑。
Google 的克隆在另一個產品(Cloud TTS 的 Chirp 3 Instant Custom Voice),
且是 allow-list 邀請制。

**選 Gemini = 放棄「你自己的聲音」。這是不可迴避的取捨。**

## 五、OpenRouter vs 直接打 Gemini API

| | 直接打 | OpenRouter |
|---|---|---|
| 風格提示 | ✅ | ✅ **零損失**(寫在文字裡) |
| 行內標籤 | ✅ | ✅ |
| 30 個音色 | ✅ | ✅ |
| 多說話者 | ✅ | ❌(單人旁白用不到) |
| `gemini-2.5-pro-tts` | ✅ | ❌ 只有 3.1-flash |
| `seed` | ✅ | 有列出但**實測無效** |

**實質損失只有多說話者和 pro 版模型。**

## 六、必要的工程細節

- `response_format` 只吃 `pcm`(給 `mp3` 會 400)。裸 PCM 無檔頭,
  是 **24kHz / 16-bit / 單聲道**,自己包 WAV。
- **必須有重試層**:官方文件承認會偶發回傳空音訊。
  `pipeline/tts.py` 內建重試 + 提示降級階梯。
- 判斷成功不能只看 HTTP 200 —— 要檢查 body 長度(>2000 bytes)
  且 content-type 不是 JSON。
