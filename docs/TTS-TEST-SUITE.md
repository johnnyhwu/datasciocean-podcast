# TTS 中英夾雜測試集(DataSci Ocean Podcast)

用途:評估 TTS 引擎能否正確處理「繁體中文為主、密集夾雜英文技術術語」的語音合成。
用法:把「測試句」欄的文字原樣丟進各家 TTS,對照「該怎麼唸」欄逐句檢查,在「結果」欄記錄。

---

## 第 0 關:自然度 gate(C 組之前)

**實測發現:自然度在 C 組之前就決定生死。** 一個引擎若聽起來像機器人,
術語唸得再準也無法用於 podcast,而發音詞典與 SSML 都救不了這一層。

因此選型順序為:**先聽一句判斷自然度 → 過關才跑完整 C 組 → 再跑 A/B/D/E**。
這道 gate 極便宜(聽 10 秒即可判斷),放在最前面可省下大量無謂測試。

判讀時要區分兩種不同性質的失敗:

| 症狀 | 層級 | 可否補救 |
|---|---|---|
| 像機器人、播報腔 | 引擎級 | **不可**,只能換模型或改 voice design |
| 單字唸錯(如「論」唸成「問」) | 音素級 | 視成因而定,見下方量化註記 |
| 英文術語腔調怪 | 可補救 | 發音詞典 / SSML |

**量化等級會造成音素級錯誤。** 本專案實測:Breeze-TTS-2 的 4-bit 量化版
會把「論文」唸成「問文」,同一句同 seed 在 full precision 版本則完全正確。
若聽到單字發音錯誤,先確認是否為量化造成,再考慮發音詞典。

## 判讀原則

1. **C 組權重最高** — 中英交界是你每句都會遇到的,這組不過關就直接淘汰。
2. **A、B 組失敗可補救** — 用發音詞典或 SSML 修正,不必因此淘汰引擎。
3. **D 組要看是否可設定** — 有些引擎可切換數字讀法模式,先確認再判定。
4. **E 組決定聽感** — 長句語調漂移無法靠後製修,是選型的硬指標。
