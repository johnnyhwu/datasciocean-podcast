# 選型與調校歷程(2026-09-04 ~ 09-07)

這份文件是給人讀的,執行 pipeline 不需要它。
它記錄的是**我們試過什麼、為什麼放棄、以及哪些直覺被實測推翻**。

---

## TL;DR

測了 **8 個 TTS 引擎**,最後選 Google Gemini 3.1 Flash TTS。
過程中三次推翻自己的判斷,兩次發現廠商文件與實際不符。

| 引擎 | 平均 sim | 價格/百萬字元 | 結局 |
|---|---|---|---|
| **Gemini 3.1 Flash TTS** | **0.990** | **$1** | ✅ **採用** |
| MiniMax speech-2.8-turbo | 0.986 | $60 | 備案 |
| MiniMax speech-2.8-hd | 0.980 | $100 | |
| Fish Audio s2-pro | 0.979 | $15 | ❌ 片段間音色不連貫 |
| Breeze-TTS-2(本地) | 0.950 | 免費 | ❌ **非商業授權** |
| Qwen Audio 3.0 TTS | 0.930 | $15 | ❌ 大陸腔、語速過慢、機器感重 |
| BlueMagpie-TTS(本地) | 0.929 | 免費 | ❌ 官方沒釋出長文工具 |
| OmniVoice(本地) | 0.960 | 免費,Apache-2.0 | ❌ 克隆抓不到口音,且無從補救 |

**一集 30 分鐘的成本從「要跟廠商談四位數美金的商業授權」變成 US$0.01。**

## 第一階段:本地開源(Breeze / Qwen3 / BlueMagpie)

### 起點

使用者的原則是「本地開發不要弄髒系統」,所以先試本地方案:
uv 管虛擬環境、pyproject.toml 記套件、模型權重放 `~/.cache/huggingface` 共用。
整個環境維持**純 MLX、不裝 torch**。

### Qwen3-TTS:兩次失敗

1. 用了 Base 模型,但 README 列的音色是 CustomVoice 變體才有的
2. 換成 CustomVoice 之後,使用者的評語是「完全不行,太像機器人了」——
   原因是我沒傳 `instruct`

### Breeze-TTS-2:一路調到很不錯,最後死於授權

這是投入最多的一個。關鍵發現:

- **4-bit 量化會改變發音。** 使用者親耳聽出「論文」的「論」被唸成「問」。
  控制實驗確認:全精度正確、4-bit 錯誤。改用 7.63GB 全精度版。
- **instruct 裡不能出現速度詞。** 寫了 "relaxed"、"unhurried" 之後,
  12 秒的文字生成出 60 秒音檔,撞到 max_tokens,跑了 947 秒。
  規則:instruct 只描述音色與情緒,絕不描述語速。
- **Voice Cloning 解決了英文腔問題。** 用使用者自己的 15.6 秒錄音當參考,
  他的評語是「基本上就是我自己唸英文的方式」。這是整個專案的高點。
- 定案設定:`cfg_scale=3`、`temperature=0.9`、`seed=42`。

**但最後查到權重是 BreezeBlue Research and Non-Commercial License v1.1**,
明文排除「creator / content monetization / small-business」例外。
podcast 一旦有贊助或會員制就違約。**一個技術上可用的方案,死在法務上。**

### BlueMagpie-TTS:論文對了,模型沒跟上

OpenFormosa 的台灣口音專用模型,論文(arXiv 2607.06054)幾乎逐字描述了
我們的情境。但實際跑整集,使用者的評語是
「每個片段音色都不太一樣,聽起來就像是接起來的」。

追查後發現:**model card 記載的長文 CLI `scripts/generate_tts.py` 根本不在
釋出的 repo 裡。** 它宣稱提供的 `--crossfade-ms`、`--chunk-rms-match-db`、
`--chunk-edge-fade-ms` 在 `src/` 全部搜不到實作。而且載入時警告有 8 個
權重參數是公開程式碼沒用到的(`duration_head`、`stop_context_gate` 等)。

**結論:權重比推論程式碼新。官方 demo 的音質靠的是沒釋出的後製功能。**

## 第二階段:轉向商用 API

### 我犯的一個錯:說 OpenRouter 沒有 TTS

我查 `/api/v1/models` 用 `output_modalities` 含 `"audio"` 過濾,
只找到 4 個(2 個是音樂生成、2 個是對話語音),於是斷言
「OpenRouter 是 LLM 聚合層,不是語音平台」。

**錯了。** TTS 模型用的是 `"speech"`,而且**預設不出現在模型清單裡**,
要加 `?output_modalities=speech` 才看得到。它其實有一整套
`/api/v1/audio/speech` API 和 17 個以上的 TTS 模型。

這個錯差點讓我們錯過最後選中的方案。

### MiniMax 的兩次修正

- 我先說它「沒有發音字典」。**錯了** —— T2A v2 有 `pronunciation_dict`,
  語法是 `"監督/(jian1)(du1)"`,拼音加聲調數字。
- 官網最低儲值 **$25**,對評估階段是個門檻。走 OpenRouter 沒有這個限制,
  但**失去 voice cloning、pronunciation_dict、emotion、speed** ——
  也就是所有讓 MiniMax 值得選的功能。

### 使用者自己做的市場調查

使用者獨立寫了一份窮盡式調查(`docs/TTS-VENDOR-SURVEY.md`),比我做的更廣。
它抓到兩個我漏掉的重點:

- **ATEN 優聲學**有「破音字自訂」,是台灣本土唯一有發音字典的商用方案
- **F5-TTS 官方預訓練權重是 CC-BY-NC**,商用必須改用 OpenF5 的 Apache 權重 ——
  這個陷阱沒發現會出事

## 第三階段:Gemini —— 幾乎每個預期都被推翻

### 它讓正規化層縮水一半以上

我們為 Breeze 建了八條正規化規則。拿原始未改寫的文字直接餵 Gemini:

| 原始寫法 | 結果 |
|---|---|
| `監督式微調` `消融實驗` `這個主張` | ✅ 1.000 —— **三個 Breeze 修不掉的破音字全對** |
| `SFT` `RLHF` `LLM` `RAG`(未加點) | ✅ 1.000 —— 加點規則不需要 |
| `48.7%` `63.7%` | ✅ 1.000 —— 中文數字化不需要 |
| `rm -rf`、`Stage 2` | ✅ —— 不再變成「Stage Wu」 |

**而且幽靈音完全消失** —— 那是 Breeze 獨有的病,不是通病。

更反直覺的是:**我們的正規化有時反而害了它。**
`48.7%` 原文 1.000,改寫成「百分之四十八點七」掉到 0.892。

**八條規則縮到三條。**

### 提示越短越好(完全反直覺)

使用者從 Claude chat 拿到一份很專業的「導演筆記」提示(角色、場景、
導演備註、範例情境,577 字)。實測結果:

| 提示長度 | 結果 |
|---|---|
| 577 字(markdown 導演筆記) | ❌ **穩定回 502 空音訊**,連續 7 次全失敗 |
| 146 字(壓縮版) | 🔶 可用但語氣被稀釋 |
| **40 字** | ✅ **最好聽,sim 1.000** |

診斷過程中還遇到另一種失敗:回傳 6.6MB(正常 1.2MB)——
**把整份導演筆記唸出來了**。

真正的觸發條件是**提示與正文的長度比例**,不是絕對長度:
45 字提示配 24 字正文必掛,配 32 字正文正常。

**原因:那套格式是為 AI Studio 的獨立欄位設計的。走 API 時提示跟正文
擠在同一個 `input`,長提示會跟正文搶注意力。**

### 三個必須接受的限制

1. **不能克隆使用者的聲音。** Gemini TTS 只有 30 個預建音色。
   Google 的克隆在另一個產品(Chirp 3),且是邀請制。
   **這是選 Gemini 最大的代價** —— 放棄了 Breeze 時期最滿意的成果。
2. **`seed` 無效。** 同一請求同一 seed 跑兩次,md5 不同、長度差 12%,
   連跑 5 次長度落在 26-32 秒。**重跑就是重骰,不能鎖定。**
3. **官方承認音色會漂移**,建議切小塊 —— 剛好就是我們的 beat 制度。

### 大陸腔:用提示詞解決

使用者的回饋是「Gemini 很棒,但大陸腔很重」。

**後製改不了口音。** 音色可以靠 DSP 調,但口音是音素怎麼發、聲調怎麼走,
在生成當下就烘進波形了。Voice conversion 能換音色但保留韻律,
會變成「用你的聲音講大陸腔」,更怪。

**但提示詞可以。** 測了六種策略(英文明示、中文明示、排除法、
BCP-47 語言碼、角色設定),使用者選中的是最短的中文那句:

> 請用台灣人的口音說話,像台北的科技 podcast 主持人那樣,語氣耐心而清楚。

## 第四階段:OmniVoice —— 唯一一次為了「你的聲音」回頭試本地方案

**時間:2026-09-07。結論:放棄,實驗目錄已刪除。**

### 為什麼值得試

選 Gemini 時被迫放棄的唯一一樣東西,就是 Breeze 時期最滿意的成果 ——
用使用者自己的錄音克隆,他當時的評語是「基本上就是我自己唸英文的方式」。

OmniVoice(k2-fsa,Apache-2.0)同時滿足三個條件:
可商用、支援 zero-shot voice cloning、支援 Apple Silicon。
而且它的生成設定裡有 `audio_chunk_duration` 與 `fade_duration`,
代表**內建長文分塊與淡接** —— 那正是 BlueMagpie 缺了才音色漂移的東西。

### 隔離做法(這次做對的事)

使用者明確要求「不要弄髒環境,不好就整包刪掉」,所以:

- **獨立 `.venv`**(1.1 GB,含 torch)—— 主環境維持純 MLX
- **`HF_HOME` 指向實驗目錄內**的 `hf-cache/`(3.0 GB)——
  刻意違反「權重放 `~/.cache` 共用」的常規,因為放共用快取會在刪除時留下 GB 級殘骸
- 專案 `.gitignore` 排除 `experiments/`

最後 `rm -rf experiments/omnivoice` 一行清掉 4.4 GB,主環境零殘留。
**臨時實驗就該這樣做。**

### 我犯的錯:參考音檔剪短了,逐字稿沒跟著換

官方建議參考音檔 3-10 秒,而使用者的新錄音是 24.8 秒。
我切了一個 10 秒版,**卻沿用整段 24.8 秒的逐字稿**。

結果模型直接**去唸參考文字而不是目標文字**:

```
預期:這裡是 DataSci Ocean,我是 Johnny…
實際:這個 agent 非常…model 主要是透過兩種方式來訓練…SFT…RLHF
     ↑ 這是參考錄音的內容
```

平均 sim 掉到 **0.175**,六段全滅。

修正後把逐字稿改成跟著音檔檔名走(`johnny2_10s.wav` 配 `johnny2_10s.txt`),
找不到就直接報錯而不是默默跑錯。

**教訓:OmniVoice 對 ref_text 的依賴比一般 cloning 模型更強 ——
不匹配時它不是降級,是改唸參考內容。**

### 參考音檔長度的影響(官方那句警告是真的)

模型每次生成都印:

> Reference audio is 24.7s long (>20s). This may cause slower generation,
> higher memory usage, and degraded voice cloning quality.
> We recommend trimming it to 3-10s.

實測完全成立:

| beat | Gemini | Omni 24.8s 參考 | Omni 10s 參考 |
|---|---|---|---|
| `b01_identity` | 0.969 | **0.839** | 0.969 |
| `b23_four_ops` | **0.993** | 0.968 | 0.964 |
| `b34_implementation` | **0.991** | 0.983 | 0.983 |
| `b45_result_main` | 0.966 | **0.986** | **0.986** |
| `b50_term_p50` | **1.000** | 0.943 | 0.971 |
| `b55_critique_reddit` | **0.978** | 0.919 | 0.884 |
| **平均** | **0.983** | 0.940 | **0.960** |

24.8 秒的參考造成兩個**內容層級**的缺陷,縮到 10 秒後都消失:

- `b50_term_p50` 漏掉整句「檻。為什麼要看這個?」
- `b01_identity` 開場白被重排,「這裡是 DataSci Ocean」變成「Side Ocean」塞進句中

**這類錯比發音錯嚴重得多** —— 聽起來很流暢,只是少講了東西,
沒有 STT 回轉驗證根本抓不到。

RTF 也從 2.2-5.3 降到 1.25-2.62(一集 30 分鐘約 1-1.3 小時,且全程佔用本機)。

### 真正的死因:克隆抓到音色,抓不到口音

使用者聽完 10 秒版的評語:**「聲音比較乾癟,而且有大陸腔」**。

他問能不能像 Gemini 那樣用提示詞把口音調成台灣腔。查了原始碼,**不行,而且是結構性的**:

**1. `instruct` 不是自由文字,是有驗證的固定詞彙表**

```
性別  男 / 女
年齡  儿童 / 少年 / 青年 / 中年 / 老年
音調  极低音调 / 低音调 / 中音调 / 高音调 / 极高音调
風格  耳语
方言  河南话 陕西话 四川话 贵州话 云南话 桂林话
      济南话 石家庄话 甘肃话 宁夏话 青岛话 东北话
```

**十二種方言全部是大陸方言,沒有台灣國語。** 寫錯直接 `ValueError`。

**2. Voice Clone 與 Voice Design 是互斥的兩種模式**

官方文件:Voice design 是「provide `instruct`… **no reference audio needed**」。
**不能同時說「用我的聲音」和「用某種口音」。**

**3. 646 種語言裡沒有台灣中文**

只有 `zh`(普通話)、`yue`(粵語)、`nan`(閩南語)。
`nan` 是台語不是台灣國語,用了會唸成台語。

### 為什麼 Gemini 可以而它不行

**Gemini 底層是 LLM,提示是自由文字,所以口音可以用自然語言引導。
OmniVoice 是擴散模型加固定條件向量,沒有這個彈性。**

這跟 BlueMagpie 的 192 維 speaker vector 裝不下口音是同一類問題:
**zero-shot cloning 普遍是音色好遷移、口音難遷移。**

### 結論

它唯一的優勢是「你的聲音」,而使用者的評價是乾癟加大陸腔 ——
**那個唯一的優勢並沒有兌現**,其他每一項(準確度、口音可控性、速度)都輸給 Gemini。

實驗目錄已刪除。

## 幾個被實測推翻的預期

記在這裡,提醒自己直覺不可靠:

| 我的預期 | 實際 |
|---|---|
| 長句會累積更多錯誤 | **相反** —— 長句反而修好語言辨識錯誤(`stage_long` 完美) |
| 用使用者的聲紋會帶來他的語速 | **相反** —— 語速反而變快(7.6 → 8.6 字/秒) |
| 幽靈音是穩定可重現的缺陷 | **不是** —— 後來同一句話 rp=1.0 就沒問題,觸發條件不穩定 |
| `repetition_penalty` 能抑制幽靈音 | **無效**,而且長句組反而變差 |
| 中文全稱比英文縮寫安全 | **不一定** —— 避開字母問題卻引入破音字問題 |
| OpenRouter 沒有 TTS | **有**,而且是最後選中的方案 |
| MiniMax 沒有發音字典 | **有**,`pronunciation_dict` |
| 提示寫得越詳細越好 | **相反** —— 577 字直接讓 API 掛掉 |
| 有 voice cloning 就能拿回台灣腔 | **不會** —— 克隆遷移音色,不遷移口音 |
| 參考音檔越長,克隆越準 | **相反** —— 24.8 秒造成漏字與句子重排,10 秒反而好 |

## 量測工具本身也是產出

`verify.py` 的比對規則修了四次,每次都是因為**分數在懲罰正確的發音**:

1. Whisper 輸出簡體 → 加 OpenCC `s2twp`
2. 「十五」vs「15」→ 中文數字正規化
3. **「Mem zero」vs「Mem0」→ 英文數字詞正規化**
   (這次修正讓 Gemini 從 0.963 跳到 0.990,**排名從第四變第一**)
4. 「百分之四十八點七」vs「48.7%」→ 小數點被標點清理吃掉,要保留

**教訓:當一個量測工具說某個方案很差,先確認不是工具在說謊。**

另外寫了 `rescore.py`,用既有轉錄結果重算分數,不用重跑 STT ——
改比對規則時能一次把所有歷史實驗拉回同一把尺。

## 最後一個發現:重複句是寫稿流程的缺陷

ep001 生成後,使用者聽出「而選項只有四個,我一個一個講」重複了兩次。

**不是 TTS 的問題,是我的寫稿順序造成的。** 我先寫完內文,
事後才插入 signpost,卻沒回頭修剪內文的第一句。整集有四處。

而 **STT 驗證完全抓不到** —— 兩段各自都唸得完全正確。

已經把字面重複的偵測寫進 `validate.py`,但換句話說的重複程式抓不到,
只能靠插完路標之後自己把相鄰兩段連起來讀一次。
