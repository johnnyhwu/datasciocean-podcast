# 音樂:片頭、章節轉場、片尾

**已定案。** Jonas Blakewood / Presentation(Pixabay),三段都從同一首切出來,
所以節目的開頭、中間、結尾共用同一個動機。

```
music/intro.wav   小節 0-1     0.65s 起   7.98s   片頭
music/sting.wav   小節 14     56.51s 起   3.99s   章節轉場
music/outro.wav   小節 31+尾  124.34s 起   6.99s   片尾
music/source/     授權原曲,cut.py 可以重切
```

**不要重新評估這個選擇。** 它是三輪盲測的結果,過程在下面。

## 怎麼選出來的

2026-09-20 定案,從 Johnny 在 Pixabay 挑的 12 首裡經過三輪。

**第一輪(12 組,絕對排名)。** 每首切出片頭與片尾兩段,放進真的節目裡
(片頭 → 真的開場白 → 一句話帶走 → 收尾 → 片尾),全部對齊 −19 LUFS。
入選四首:Alex Morgan / Podcast Intro(F)、Jonas Blakewood 的 Weekly Report(A)、
Corporate Music(E)、Presentation(J)。

**第二輪(四強兩兩對決)。** 絕對排名在這裡失效 —— 四首都過關,再聽同一段
58 秒不會有新資訊。改成六組對決,每組只有片頭接第一句話的 11–14 秒。
結果完全可傳遞,沒有循環:**J(3 勝)> F(2)> E(1)> A(0)**。

**第三輪(裁切)。** Johnny 說 J 當片頭片尾不錯但當轉場「還好」,
而兩者是同一首曲子的不同位置 —— 所以問題在位置。逐小節量過之後發現
這首幾乎全程滿編曲,只有小節 12–13(48–56 秒)與 20–21(80–88 秒)兩處留白
(鼓退開,頻譜重心從 200 Hz 跳到 620–660 Hz)。我原本拿去當轉場的是小節 0,
也就是片頭那一段,滿編曲塞進兩段旁白中間就像一塊歌掉進來。
九種裁切試聽後選了**小節 14** —— 留白之後鼓回來的那一小節,有「下一章開始」的推力。

## 三段的裁切位置

一小節 3.99 秒(60 BPM),相位 0.650 秒(從起音包絡量的)。
**長度只能是 3.99 的倍數** —— 這也是為什麼片頭是 8 秒而不是 10 秒。

| | 小節 | 起點 | 長度 | 淡出 |
|---|---|---|---|---|
| `music/intro.wav` | 0–1 | 0.65s | 7.98s | 1.6s |
| `music/sting.wav` | 14 | 56.51s | 3.99s | 0.8s |
| `music/outro.wav` | 31 + 尾巴 | 124.34s | 6.99s | 0.9s |

重切用 `uv run python music/cut.py`,參數都寫在檔頭。原曲放
`music/source/`(5.1 MB)—— 沒有它就沒辦法重切,也沒辦法證明來源。

## 章節轉場放幾次

**約每 9 分鐘一次,下限 2 上限 5**,由 `assemble.py` 的 `sting_count()`
依整集長度算。ep001 是 29.6 分 → 3 次。八個章節點全放的話平均不到四分鐘一次,
轉場會從「這裡換段落了」退化成背景噪音。

選哪幾個章節點:**枚舉組合,取「最長一段沒有標點的區間」最短的那一組。**
第一版用等距目標的最近鄰,在 ep001 上把三次全擠在前 18 分鐘,最後 11 分鐘
一次都沒有 —— 那一段的章節點本來就稀疏,最近鄰會一直往前挑。

## 鋪底 BGM 的決定:不做

量測條件:ep001 的 b02+b03(64.5 秒連續旁白),鋪底用 Lemon Music Studio /
Inside You,只統計真的在講話的時段。表格是音樂相對人聲的能量(dB)。

| 頻帶 | 寬頻 −26 dB | 寬頻 −20 dB | 寬頻 −14 dB |
|---|---|---|---|
| 低頻 80–250 Hz | −28.9 | −22.9 | −16.9 |
| 母音 250 Hz–1 kHz | −30.1 | −24.1 | −18.1 |
| **子音 1–4 kHz** | **−24.6** | **−18.6** | **−12.6** |
| 齒音 4–8 kHz | −39.2 | −33.2 | −27.2 |

關鍵是子音那一列比寬頻設定值高 6–7 dB —— 曲子的能量本來就集中在 1–4 kHz,
而那正好是分辨「記憶」跟「機制」的頻帶。經驗門檻是子音帶要低 20 dB 以上,
所以 −26 安全但幾乎聽不見、−20 已經在邊緣、−14 明顯蓋話。

第二個理由跟這個專案特有:輸出有 1.1× 到 1.5× 六個加速版本,而加速是
WSOLA。拉伸人聲很乾淨,拉伸音樂會打散它的週期性,產生顆粒感與節奏抖動。
鋪底會讓五個加速版本全部劣化。

**結論:音樂只當標點,不當底色** —— 片頭、章節轉場、片尾。beats.json 的
`chapter` 欄位已經標了八個章節點,轉場音效直接用片尾段落,不必另找素材。

## 先前試過自己生成:五輪之後放棄

用 ACE-Step 1.5 在本機生成(MIT 授權),跑了五輪盲測,Johnny 的結論是
**深層的結果都不滿意**,於是整個方向放棄,環境(29 GB)整包刪除。
**不要重建** —— 重建的成本是 29 GB 加上好幾小時,而它已經被人耳否決過五次。

那五輪唯一的產出是一份規格,而那份規格**後來被證明不描述 Johnny 的喜好**:
它推出「Rhodes 電鋼 / 無鼓無貝斯 / 暖而不亮」,而 Johnny 從 Pixabay 選的
四首入圍曲**全部有鼓**,三首是同一個作者的商務簡報風。我照那份規格推薦的
兩首(Lemon Music Studio、Corporate Music)一首被列為不能選、一首只拿一勝。

**教訓:用模型生成的候選去推導的「偏好規格」,只在那批候選的分布裡有效。**
換一個素材來源就不成立了。

### 五個還可以用的技術發現

1. **`use_cot_caption=True` 是預設值,它會讓 5Hz LM 把 caption 整個改寫。**
   「Rhodes + 鐵琴 + 不要打擊樂」被改寫成「chillhop… neo-soul groove…
   兩把電吉他… boom-bap 鼓機」。所以前三輪所有「某個樂器聽起來如何」的
   歸因全部不可靠 —— 送進 DiT 的根本不是我寫的那段字。
2. **但關掉改寫讓結果更糟。** 盲測第一名是改寫開著的 2B,最後兩名都是
   關掉改寫的 2B。terse caption 對 DiT 太稀疏,LM 的膨脹反而更接近它的訓練分布。
   正確做法是**用 LM 自己的文體寫 caption**,讓改寫趨近恆等變換。
3. **約束要寫成正面的編曲事實才躲得過改寫。** 「There is no drum kit and no
   bass: the whole piece rests on the Rhodes and the vibraphone alone.」
   原樣通過;而 `no percussion` 被反轉成 boom-bap 鼓機。
4. **`offload_dit_to_cpu` 在 Apple Silicon 上是空操作。** 兩種模式量出來
   一模一樣的 19.6 GB,系統可用都掉到 0.6 GB —— 統一記憶體下 CPU 與 GPU
   共用同一塊實體 RAM,搬過去等於沒搬。XL(4B)會被系統的記憶體壓力機制砍掉,
   2B 只用 10.0 GB 且每首 4-45 秒(XL 是 170-390 秒)。
   而「XL 比較好」始終沒有證據支持 —— 兩次對照都是兩個變數同時變了。
5. **`cover` 任務(換配器、保留旋律)不可靠,而且忽略 `duration`。**
   輸出長度完全繼承來源。同樣 strength 0.7 的四首,音高分布相關性從
   **+0.955 掉到 −0.210**(兩首無關曲子的基準線是 −0.345),調高到 0.9
   也沒變好(+0.366 / +0.425)。所以「片尾 = 片頭動機的收束版」靠它做不出來。
   **附帶一條方法學:波形相關性接近 0 不代表旋律被丟掉** —— 換配器本來就會讓
   波形完全不同,要看音高分布才有意義。

完整的五輪 prompt、seed 與逐首結果在 git 歷史(commit 608f50a 與 bdbd63b 之間的
`docs/INTRO-MUSIC.md`,那是 `MUSIC.md` 改名前的檔名)。**沒有留在這裡的理由是它已經不可重現** ——
環境刪了,而且不該重建。
