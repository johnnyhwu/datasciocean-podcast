# 逐字稿正規化規則(Gemini TTS 版)

逐字稿是 single source of truth。這裡列的是**寫稿時就要用的寫法**,
不是事後再套一層轉換 —— Gemini 幾乎什麼都唸得對,需要改寫的情況
少到直接寫進稿子最簡單。

**大原則:能不改就不改。** 實測 `48.7%` 原文 1.000,改寫成
「百分之四十八點七」反而掉到 0.892。

---

## ✅ 直接照原文寫,不要動

以下全部實測 sim = 1.000:

| 類型 | 直接寫 |
|---|---|
| 縮寫 | `LLM` `SFT` `RLHF` `RAG` `PPO` `GRPO`(**不要加點**) |
| 百分比與小數 | `48.7%` `63.7%` `39.4%` |
| 模型名 | `GPT-4o` `GPT-4o-mini` |
| 破音字 | `監督式微調` `消融實驗` `這個主張` `預設` |
| 符號指令 | `rm -rf` |
| 英文接數字 | `Stage 2` |

---

## ⚠️ 這三類仍然要改寫

### R1 版本號與參數量 —— 拆開寫

實測 `Qwen-3.5-9B` 被唸成「Quant 3.6」,`27B` 唸成「27 幣」。這是最嚴重的一類。

```
Qwen-3.5-9B           ->  Qwen 3.5 的 9B 模型
distilbert-base-cased ->  distilbert 的 base 版本
BERT-large            ->  BERT large
```

### R2 符號與科學記號 —— 拼出唸法或改寫

```
ρ = -0.44   ->  相關係數大概是負零點四四      (原文唸成「Row 等於負 0.44」)
5e-6        ->  五乘以十的負六次方            (原文唸成「51-6」)
SC@64       ->  抽樣六十四次                 (原文唸成「SC at 64」)
DSF+RAG     ->  領域微調再搭配 RAG
LLM-as-a-Judge -> 讓語言模型自己當評審
```

### R3 檔名 —— 第一次給全名,之後用中文代稱

實測 `CLAUDE.md` 被唸成「cloud.md」,`checked in` 唸成「check 定」。

```
一份被 checked in 的 CLAUDE.md 會被讀取
  ->  一份簽進版控的設定檔會被讀取,它的檔名是 CLAUDE 點 M D
```

## 特例:同名容易混淆的專有名詞

不是為了修發音,是為了**讓聽眾分辨得出來**。

```
Mem0        ->  Mem zero
Mem0^g      ->  Mem zero graph 版
```

判準:如果兩個名字唸出來會一樣、或差異小到耳朵抓不到,就要主動拉開。
podcast 沒有字幕,聽眾分不出來整集就白講了。

---

## 檢查方式

寫完稿子跑 `pipeline/validate.py`,合成後跑 `pipeline/verify.py`。
**STT 是篩選器不是判官** —— 低分只代表要人耳確認,Whisper 自己也會聽錯
(例如「不在記,在忘」被寫成「不再記,再忘」,那是同音字不是唸錯)。
