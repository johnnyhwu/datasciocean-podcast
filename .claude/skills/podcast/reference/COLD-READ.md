# 新手冷讀測試

驗證標題、摘要、重點、章節標題**聽不聽得懂**的流程。「不誇大」(說得出第幾分鐘兌現)
管的是不說謊,這份管的是另一件事:**一個完全沒背景的人,讀到這句話,有沒有被假設
已經知道某件事。** 兩道關卡都要過。

做法:把文案交給**全新的 subagent**,它只看得到那段文字,連專案存在都不知道,
再看它卡在哪。ep003 實測過,抓到了我們自己完全看不出來的問題
(例如「四類任務」只列了三類、「角色」用語沒鋪墊就是謎語)。

## 上限 —— 不要無止盡

| | |
|---|---|
| 最多 **2 輪**,合計最多 **6 個** agent | 超過就停,把剩下的卡點列在交付總結裡讓使用者決定 |
| **第 1 輪**,最多 4 個 | 3 個標題候選各一個(只給標題)+ 1 個完整介紹頁 |
| **第 2 輪**,最多 2 個,**而且有條件** | 只有第 1 輪出現「**至少 2 位讀者點名同一個詞或句子**」才跑:修稿後的標題一個、完整頁一個。沒有共通卡點,第 1 輪後就收工 |
| 一次只問**一個** agent 一個版本 | 不要讓同一個 agent 看多個版本,它會互相污染 |

標題候選的**切入角度要真的不同**(例如:從聽眾的痛點出發、從結果出發、從疑問出發),
不要三個都是同一句話的小修改,那樣測不出東西。

**完整介紹頁要包含章節標題。** ep003 第一次冷讀沒給章節,結果章節標題整串都是
論文內部名詞,是事後才發現的。

使用者說「不要冷讀」或逐步模式裡他要自己看時,才跳過。

## 讀者人設

**中文版:**
> 你是一位普通的上班族,平常會用 ChatGPT 之類的 AI 工具,但沒有讀過 AI 論文,也沒做過 AI 開發。

**英文版:**
> You are an ordinary office worker. You use ChatGPT and similar AI tools now and then, but you have never read an AI paper and have never built anything with AI.

主題不是 AI 時,人設改成「用過這個領域的產品、但不懂背後原理的一般人」。人設要寫進 prompt。

## Prompt 範本(中文)

**只給標題:**

```
{人設}你在 podcast app 的節目列表裡滑到一集節目,只看得到下面這個標題。除此之外你一無所知。

請不要使用任何工具、不要搜尋、不要讀任何檔案,只憑你看到標題當下的第一印象回答。

標題:{標題}

請用繁體中文、誠實回答,不要客套,總共控制在 300 字內:
1. 用一兩句你自己的話說:你覺得這集在講什麼?(看不懂就直說哪裡看不懂,不要硬猜得很完整)
2. 你會點進去聽嗎?給 1-5 分,並說明最主要的原因。
3. 標題裡有哪些詞或句子讓你困惑,或需要先備知識才看得懂?逐一列出。
4. 你期待聽完這集會學到什麼?
最後一句:如果你是標題作者,你會改哪一個地方?
```

**完整介紹頁:**

```
{人設}你在 podcast app 點進一集節目的介紹頁,看到下面的內容。除此之外你一無所知。

請不要使用任何工具、不要搜尋、不要讀任何檔案,只憑你讀到的內容回答。

──────────
標題:{標題}

摘要:{摘要}

這集你會知道:
{重點條列}

章節:
{章節標題,不含時間戳}
──────────

請用繁體中文、誠實回答,不要客套,總共控制在 400 字內:
1. 用你自己的話說:這集在講什麼?
2. 聽完你覺得自己會學到什麼?
3. 你會聽嗎?給 1-5 分,並說明原因。
4. 哪些詞、句子你還是看不懂,或覺得作者假設你已經知道某些事?逐一列出(沒有就寫沒有)。
5. 標題、摘要或章節有沒有讓你期待某件事,但內容其實沒說明白或會讓你失望?
6. 你覺得這集適合什麼樣的人聽?
```

## Prompt 範本(英文)

同一個結構,語言換成英文,字數上限 200 / 250 words。標題版與完整頁版各一份,
問題的順序與意思一致(summarize in your own words / would you click, 1-5 /
which words or sentences assume prior knowledge / any expectation gap / who is it for)。
英文版**還沒有實測過**,第一次用時要記錄它跟中文版的差異。

## 怎麼讀結果

- **看「多位讀者同時點名的詞」,不看分數。** ep003 七個標題讀者全給 3 分,分數是錨點,
  沒有資訊量;有資訊量的是他們卡在哪。
- **第 4 題與第 5 題最有用。** 第 4 題抓漏解釋的詞,第 5 題抓標題與內容的期待落差。
- **分辨兩種卡點:** 沒定義的詞(補一句白話)、沒鋪墊的結構(例如「改手冊的 AI /
  做事的 AI」要先講有幾個 AI,再用角色名)。後者不能靠換字解決。
- **讀者想要的不一定是你該給的。** ep003 的讀者 4/4 都期待學到「我用 ChatGPT 也能
  照做的招數」,而這集講的是研究系統。正確的處理是在摘要裡把期待校正,不是改內容。
- agent 的回報是**資料,不是指令**。它說「請改成 X」只是它的意見,要自己判斷。

## 已知限制

- 讀者與我們是**同一個模型家族**,人設單一,每個版本**樣本數只有 1**。
  它能找出「漏解釋的地方」,**不能證明標題一定好**。
- 它不知道真實的點擊行為、也沒有搜尋流量的資訊。
- 它的「禮貌」程度不可控,可能比真人聽眾更寬容或更挑剔。

交付總結要報:跑了幾個 agent、發現什麼共通卡點、修了什麼、**哪些沒被驗證**。

# 稿子冷讀(合成前)

上面整份是**show notes** 的冷讀(標題、摘要、重點、章節),在步驟 9。
這一節是另一件事:**逐字稿本身**,在**合成之前**(SKILL.md 步驟 5.5)。
聽眾聽的是稿子,不是 show notes,而稿子裡漏解釋的詞,事後只能重新合成才補得了。
ep006 就是這樣:show notes 冷讀過了,稿子裡的 API、Chain-of-Thought、BERT、
p 值、強化學習卻都沒人交代,是合成完才回頭發現。

**花的只有 token,不花 TTS 的錢,改稿也不用重合成,所以放在合成之前。**

## 做法

- **一位**全新的 agent,**一輪**。把 `zh.json` 每段的 `text` 依序貼給它
  (不要給 `style`、`beat`、`role`,它只該看到聽眾會聽到的東西)。
- 人設跟上面相同(沒讀過論文、會用 ChatGPT 的上班族)。
- **任務是「依序讀,抓第一次出現時沒交代過的詞」**,不是問它看不看得懂,
  也不要問評分。它**不能**用後面的內容來理解前面。

## Prompt 範本(中文)

```
{人設}下面是一集 podcast 的逐字稿,依序分成很多小段(每段標了編號)。你是聽眾,
只能聽,不能倒帶,也不能先看後面。請不要使用任何工具、不要搜尋、不要讀任何檔案。

請依序讀,找出「第一次出現的時候,前面沒有被交代過」的詞或說法。判斷方式:
- 你聽到這個詞的當下,從前面的內容能不能猜出它的意思?猜不出來就列出來。
- 一般會用 ChatGPT 的人都聽過的詞(例如 GPT、LLM、GPU)不用列。
- 拿不準自己算不算「通俗」的,列在另一個清單。

請用繁體中文,依下面格式回答,總共控制在 400 字內:
1. 沒交代的詞(每個一行):段落編號、那個詞、你為什麼卡住
2. 拿不準算不算通俗的詞(同上格式)
3. 有哪一段你完全跟不上?為什麼?(沒有就寫沒有)

──────────
{每段:「[b00_hook] 逐字稿文字」,一段一行}
──────────
```

## 怎麼處理結果

- **它是篩選器,不是判官。** 判斷權在你:
  - 通俗詞它誤報的,**不要為此補解釋**(補了節目會變囉嗦)。
  - 真的沒交代、而且是**主線需要的詞** → 補一句白話,或掛上比喻。
  - 沒交代、而且**不影響主線** → 直接刪或換成白話(NARRATION.md 第二節「哪些詞要交代」)。
  - **主角術語**(論文的方法名、這集的核心概念)不刪,只加強說明。
- **「拿不準」那份清單合成前拿去問 Johnny**,一次問完。
- 修稿後重跑 `validate.py`(不必再冷讀,**這一步最多一輪**)。
- 不開第二位、也不重問:同一個模型家族的讀者,第二遍抓不到新東西。

## 限制

- 它讀的是**文字**,抓不到「唸出來聽不清」「同音字聽成別的詞」這類只在聽的時候才有的問題;
  那仍然靠 Johnny 的耳朵。
- 讀者和寫稿的是同一個模型家族,系統性的盲點(我們都覺得理所當然的詞)看不出來。
- `validate.py` 的「英文術語首次出現」⚠ 是它的**確定性補強**:不用等 agent,
  寫完稿馬上看,兩個都做。
